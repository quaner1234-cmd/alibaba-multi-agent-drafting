This is a public template, not the private operational dispatch. Replace all
placeholders with an authorized local handoff before execution. Browser helpers
mentioned here are described in [tooling status](../docs/tooling-status.md), not
distributed as runnable dependencies of this repository.

You are the human-selected executor. Serially complete exactly these five prepared
products: `<PRODUCT-1>` through `<PRODUCT-5>`, using `<PINNED-HANDOFF>` and each
versioned card. Save inquiry-product drafts only; do not submit or publish.

1. Read the actual project rules and your supported browser documentation once.
   Confirm the correct company/account and task-owned session/tab. Inspect existing
   ownership/results; continue your own partial target. Before genuinely creating a
   product, make one current platform duplicate check. Missing results do not establish
   that another agent has not started.
2. Consume the prepared title, fields, local image order and registered bank references.
   Do not re-search, unpack/reselect, authenticate photos, replay videos or audit old
   assets. Confirm condition and tier policy for this batch before filling; do not
   inherit a different batch's commercial decisions.
3. On the first normal product, try `<CLEAN-COPY-SOURCE>` through the real copy UI.
   If unavailable, record that once and use `<WORKING-COPY-SOURCE>`. Do not create an
   extra test product, invent a URL or modify the source. Bind an actual changed
   source in a separate execution-card version before running guarded helpers.
4. Keep correctly inherited category/unit/approved condition/MOQ/lead time and company
   content. Replace codes, product-specific prices/weight, five main images, four
   details and both product videos. Clear inherited unrelated product scenes, not
   company content. Apply `<APPROVED-COMPANY-MODULE>` once only when needed.
5. Use the supported bounded media helper to perform the repeated UI steps inside
   one invocation. It must retain fresh-observation/target guards and stop unknown
   write effects. A known missing/conflicting registration can use its selected local

   attempts or a new audit. Register the actual ordered UI receipt.
6. Save once through the verified real Save control and capture the actual result/ID.
   If its outcome is unknown, reconcile the original request/server first. On the
   same-ID server page reached after save, read fresh server data directly; otherwise
   open a controlled reader. An unsaved form is not server readback.
7. Check actual fields, both video associations and light image counts/first image/
   basic order/obvious mixups. Use the ordered UI receipt for known server naming
   changes. Unresolved order gets a narrow check, not a fabricated PASS. Record the
   actual score; a complete 4.9 does not require repeated work for 5.0.
8. Keep the same target/card through model changes. Record start/end wall time and
   automatic command/phase timing separately. Write the result, then immediately
   continue the next assigned product. A successful first product is not the end.
9. Finish after all five are completed, legitimately skipped, or safely isolated with
   explicit gaps. A global account/tool blocker may end early with preserved state.
   Report each product as `alias | draft ID (private) | score | gaps | wall time`, plus
   first-product inheritance and helper/fallback observations. Do not ask for routine
   confirmation between products, dispatch another agent or kill shared browsers.

Clean only your task-owned tabs/session. Human review/publication remains separate.
